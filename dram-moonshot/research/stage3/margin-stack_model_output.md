## 4. Raw BER, BCH t=8 and erasure flags

- BCH t=8 over 592 bits at raw BER 1e-04: P(codeword fail) = P(>8 errors) = **2.33e-17** per read. This is the concept's contract level and the target used below (at 100 GB/s, 64 B reads: one DUE per ~0.9 server-years).
  - raw 3e-05: 4.77e-22
  - raw 1e-04: 2.33e-17
  - raw 2e-04: 1.13e-14
  - raw 3e-04: 4.13e-13
  - raw 1e-03: 1.45e-08
- Errors-and-erasures decoding (fail if flagged + 2 x confident > 16), pure Gaussian noise at s = 3.72: the best flag window w = 0.42 sigma gives fail 5.7e-20 (vs 2.3e-17 hard). It flags 83% of errors but also 3.9e-04 correct bits per bit (3.9x the error rate): false flags eat the erasure budget, so flags are worth

- Pure Gaussian with flags: raw BER can rise to 1.7e-04 (s = 3.58), a 1.04x margin gain on top of ECC's 1.88x. At 80% flaggable it is 1.4e-04 (1.01x).
- **Clustering is the real threat.** If just 1% of errors arrive as 2-bit pairs in one codeword, the allowed raw BER falls to 6.3e-05 (hard) / 6.3e-05 (80% flaggable); at 10% pairs it is 1.7e-05. The DRAM Bender study must measure the pair fraction, not only the flagged fraction.

Where flags DO pay: a weaker code. Smallest designed distance (d-1 = flagged + 2 x confident budget) meeting the target at raw BER 1e-4:

| errors flaggable | min d-1 | ~check bits (10 per t-equivalent) | vs 80 for hard t=8 | array area saved |
|---|---|---|---|---|
| 0% | 16 | 80 | -0 | 0.0% |
| 80% | 16 | 80 | -0 | 0.0% |
| 100% | 16 | 80 | -0 | 0.0% |

Result: a single resolution-time flag window buys ~4% in sense margin and does not even shorten the code at this target, because
a window wide enough to catch most errors also flags ~4x as many correct bits. Flags are not a capacitor lever. Their value is
diagnostic (separating small-|dV| errors from confident ones) and weak-cell telemetry for scrubbing; multi-trial Chase/GMD soft
decoding might reach the ~1.1-1.2x of Stage 2 I-04613. The concept's '>=80% flagged' go criterion is therefore secondary;
the pair (same-codeword cluster) fraction below is the criterion that matters.

- Codewords run along a row, so each bit passes a different segment amp and comparator: static offsets are iid across a codeword.
  A bad segment amp touches 32 cells in one column = 32 different rows = 32 different codewords (one bit each). Row-level
  causes (a weak wordline, hammer on one row, a VRT pair on adjacent cells) are what create same-codeword pairs.

## R8. ECC parity, latency and access granularity (CIRC-02, CIRC-05)

- Parity: BCH t=8 is 80 check bits per 512 (15.6%) against the baseline's 6.25% on-die ECC: x1.0882 array bits.
  Array is 70% of the 4F2 PUC die, so die x1.062 (CIRC-02 applied x1.088 to the whole die; the
  array-only scaling is used here, plus 0.5% of die for per-bank decoders).
- Raw BER 1e-04: 5.75% of codeword reads take the BCH slow path (+~15 ns); mean +0.86 ns.
- Raw BER 1e-05: 0.59% of codeword reads take the BCH slow path (+~15 ns); mean +0.09 ns.
- Raw BER 1e-06: 0.06% of codeword reads take the BCH slow path (+~15 ns); mean +0.01 ns.
- 1e-4 is the 85 C worst-pattern design corner; the slow path is a p95 tail only near that corner. A 592-bit on-die
  codeword fits wide-IO parts (HBM pseudo-channel, LPDDR x16 BL32 = 512 bits per access). For DDR5 x4 RDIMMs the code
  moves to the module side band (512 + 128 bits, BCH-12, RAW-BER CONTRACT): no extra array bits and no on-die decode,
  but chipkill is given up. Narrow writes on on-die codewords are read-modify-write, as in DDR5 on-die ECC.
